# Docker 部署

## 受管应用

先准备支持 Canvas 授权集成的 New API，前提见[快速开始](/docs/overview/quick-start)。将 `canvas-server/.env.example` 复制到仓库外的私有环境文件，填写配置后执行：

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose --env-file /path/to/canvas.env -f docker-compose.managed.yml up -d --build
```

该拓扑通过 3000 端口上的 Nginx 提供 Vite 静态前端，并启动仅内部访问的 3001 端口 Canvas BFF。BFF 必须能够访问 `NEW_API_URL`，浏览器必须能够访问 `NEW_API_PUBLIC_URL`。

在 3000 端口前配置 HTTPS 入口并保留公开 Host，将 `CANVAS_ORIGIN` 设置为该精确公开源地址；在 New API 注册 `<CANVAS_ORIGIN>/auth/callback`，客户端 ID 与密钥需双方一致。`CANVAS_PROXY_READ_TIMEOUT` 按网关实际允许的生成及流式请求时长设置，Compose 要求显式填写，不提供额外经验默认值。

`canvas_private_data` 数据卷仅保存 BFF 授权状态，不保存项目或媒体；重启时保留该卷和 `CANVAS_SESSION_ENCRYPTION_KEY`。浏览器业务数据保存在按授权用户隔离的 IndexedDB，退出保留已保存数据；生成请求和参考媒体仍经 New API。

根目录 `docker-compose.yml`、`docker-compose.local.yml` 和单独静态镜像不包含完整受管服务。Docker 静态资源路径、真实 HTTPS 双站授权及生产升级回退仍待验收；部署后先检查登录、模型列表及本地保存重载，再验收付费生成。

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

文档站与 Vite 主应用、Canvas BFF 分开部署，启动文档站不会建立画布授权或模型转发能力。浏览器不持有服务商 API Key，提示词目录通过 BFF 读取，当前不提供 WebDAV 或云同步。

## 统计分析（可选）

受管 Compose 默认未启用统计，Content Security Policy 也禁止外部脚本和连接。独立静态镜像的统计环境变量不能直接保证在该拓扑中生效，不要为照搬旧部署示例放宽受管安全策略。
