# Docker Deployment

## Managed application

Prepare New API with Canvas authorization integration first; see [Quick Start](/docs/overview/quick-start). Copy `canvas-server/.env.example` to a private environment file outside the repository and fill in its values before running:

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose --env-file /path/to/canvas.env -f docker-compose.managed.yml up -d --build
```

This starts the Vite static frontend behind Nginx on port 3000 and a private Canvas BFF service on port 3001. BFF must be able to reach `NEW_API_URL`; the browser must be able to reach `NEW_API_PUBLIC_URL`.

Place an HTTPS ingress in front of port 3000, preserve the public Host, and set `CANVAS_ORIGIN` to that exact public origin. Register `<CANVAS_ORIGIN>/auth/callback` with the same client ID and secret in New API. Configure `CANVAS_PROXY_READ_TIMEOUT` to match the gateway's accepted generation and streaming duration; the compose file deliberately requires an explicit value.

The `canvas_private_data` volume stores BFF authorization state, not projects or media. Preserve that volume and `CANVAS_SESSION_ENCRYPTION_KEY` across restarts. Browser business data stays in IndexedDB, partitioned by authorized user; logout retains saved data. Generation requests and reference media still go through New API.

The root `docker-compose.yml`, `docker-compose.local.yml` and standalone static image do not provide the complete managed topology. Docker static-resource paths, real HTTPS authorization, and production upgrade/rollback still require acceptance testing. After deployment, verify sign-in, model listing and local save/reload before testing a paid generation.

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The documentation site is separate from the Vite application and Canvas BFF. Its deployment does not establish Canvas authorization or a model relay.

## Optional analytics

The managed compose file does not enable analytics, and its Content Security Policy blocks external scripts and connections. The standalone image's analytics environment variables do not by themselves enable analytics in this topology. Do not weaken the managed policy just to copy a standalone deployment example.
